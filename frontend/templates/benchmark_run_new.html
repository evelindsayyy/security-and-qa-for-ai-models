How to fill in the model

Gateway — models already on the Duke LLM gateway. No extra setup.

  1. Pick a model from the dropdown (same id as the catalog).
  2. Choose a benchmark and start the run.

Example: GPT 4.1 Mini

Hosted — Hugging Face serves the model via Inference Providers. No GPU or DCC needed.

  1. Find a model with the Inference Available spark on HF models.
  2. On the model page, open Inference Providers and confirm at least one provider is listed.
  3. If the model is gated, accept the license on that page first.
  4. Create a fine-grained token with Make calls to Inference Providers (add gated-repo read if needed).
  5. At Inference Providers settings, set routing to Automatic or enable the provider shown on the model page.
  6. Model field: paste the repo id — org/model. If you get “not supported by any provider”, pin one: org/model:provider (provider name is on the model page).
  7. Token field: paste hf_… (used once for this run, not stored).

Examples:

  • meta-llama/Llama-3.1-8B-Instruct — accept Meta license first
  • Qwen/Qwen2.5-7B-Instruct — ungated smoke test
  • TinyLlama/TinyLlama-1.1B-Chat-v1.0:featherless-ai — pin Featherless

Don't see "Chat Completion"? Many LLM pages only show Text Generation in that widget — that's normal for instruct models. Our Hosted path uses HF's chat-completions API; use View Code Snippets or the playground to confirm it accepts conversational messages.

Usage is metered (free tier + paid). Partial runs show coverage in the log if credits run out.

Custom — any server on your machine or network that speaks the OpenAI chat API. vLLM is optional; use it only if you still need to spin up a model.

  1. Already have an API? Paste its base URL and the model id it expects — no vLLM required.
  2. Need to serve a HF model? Start vLLM, Ollama (OpenAI mode), or similar — then use that endpoint's base URL and model id.
  3. From a laptop: if the API runs locally, use http://localhost:8000/v1. If it runs on a remote node, tunnel first:
    ssh -N -L 8000:<host>:8000 user@login
  4. Model field: whatever your API's model parameter accepts (e.g. my-finetune, llama3, Qwen/Qwen3-0.6B).
  5. Base URL: OpenAI-compatible root, usually ending in /v1.
  6. API key: your server's key, or leave blank / use a placeholder if auth is off.

Examples:

  • Your API — model team-chat-v2, URL http://localhost:8080/v1
  • vLLM on DCC — model Qwen/Qwen3-0.6B, URL http://localhost:8000/v1 (tunneled)
  • Ollama — model llama3.1, URL http://localhost:11434/v1

The benchmark runner only needs chat completions — not a specific serving stack. Base URL must be reachable from where this app runs (localhost, private IP, or *.duke.edu).
