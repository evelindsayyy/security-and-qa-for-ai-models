How the eval page works

This page compares language models on real Duke IT tasks. An LLM-as-judge grades each model's answers, and the results land in the report card below.

  1. Start a run Click ▶ Start eval, choose the models to compare and one or more task suites. Each suite is a different Duke use case (e.g. email drafting, SQL, policy Q&A).
  2. Let the judge score it Every answer is graded against a reference answer on a rubric (accuracy, tone, and so on). Finished runs appear as rows in the table below.
  3. Compare models Each row is one model on one suite. Sort by Overall for raw quality, Quality per $ for value for money, or drag the Value weights to match your own priorities.
  4. Dig into the detail Click any row (or a cell in the Compare matrix) to see every question, the model's answer, and the judge's score and reasoning.

How to read the table

Score columns
One score per thing the judge graded (accuracy, tone, …), usually 1–5. Higher is better; "—" means not graded.
Overall
The main quality score, 0–5. Compare models by this.
Quality per $
Quality per dollar — how much quality you get for the price. Higher is better. N/A for free self-hosted models.
Value
Your custom quality-vs-cost score, set by the weights above. Higher is better; only compare within one suite.
⚠ empty
The model gave no answer (usually out of tokens). Re-run with more tokens before comparing.
